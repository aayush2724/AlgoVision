# Deploying AlgoVision — Vercel (frontend) + Render (API + ML)

The browser only ever talks to the Vercel origin. `vercel.json` rewrites
`/api/*` to the Render backend, which means **no CORS and no API URL baked
into the frontend** — the same arrangement the Docker nginx already uses
locally.

```
browser ──► Vercel (static frontend)
               │  /api/* rewrite
               ▼
            Render: algovision-api ──► Render: algovision-ml ──► LLM provider
```

## 1. Render (do this first — Vercel needs the API hostname)

1. New ▸ Blueprint, point it at this repo. `render.yaml` defines both services.
2. Set the two values marked `sync: false`:
   - `algovision-ml` ▸ `GROQ_API_KEY` — your key. Without it the service still
     runs and the backend falls back to offline narration.
   - `algovision-api` ▸ `BACKEND_CORS_ORIGINS` — your Vercel origin. Not used
     by the rewrite path, but it matters if anything calls the API directly.
3. `INTERNAL_TOKEN` is generated by Render and shared between the two services
   automatically. Don't set it by hand.
4. Note the API's hostname, e.g. `algovision-api.onrender.com`.

## 2. Vercel

1. Import the repo. No build command, no framework — it is static.
2. Edit `vercel.json` and replace the rewrite destination with the hostname
   from step 1.4 if it differs from `algovision-api.onrender.com`.
3. Deploy.

## Things that will bite you

- **Render free tier sleeps.** After ~15 minutes idle the first request takes
  ~30s while the container wakes. The UI has offline fallbacks, so traces keep
  working; AI narration will be slow on the first call.
- **The ML service is not open to the world.** It rejects any caller that is
  neither on a private IP range nor carrying a matching `X-Internal-Token`.
  That is why `INTERNAL_TOKEN` has to match across the two services — locally
  the private-network check covers it and the token stays empty.
- **Rate limiting is per instance.** `slowapi` keeps its counters in memory,
  which is correct on a single Render container. If you ever scale to more
  than one instance the limits become per-instance; move to Redis storage then.
- **Nothing is persisted.** Student progress lives in the browser's
  localStorage, so there is no database to provision and no migration to run.
